# กลยุทธ์: ทำอย่างไรให้ผู้ใช้ "พูดภาษาอังกฤษได้จริง"

> เอกสารวิเคราะห์จากแอปเรียนภาษาที่ประสบความสำเร็จในตลาด + งานวิจัย + สถานะปัจจุบันของแอปเรา
> เป้าหมาย: ผู้ใช้พูด/ฟังภาษาอังกฤษในชีวิตประจำวันได้ โดย**ไม่เน้นไวยากรณ์** เน้นการสื่อสาร

---

## 0. สรุปสั้น (อ่าน 1 นาที)

**แอปที่คนพูดได้จริงไม่ได้ขาย "บทเรียน" — ขาย "การได้พูดทุกวันโดยไม่กลัว"**

3 กลไกที่ทำให้เกิดผลจริง (ยืนยันด้วยงานวิจัย):

| # | กลไก | แปลว่าในทางผลิตภัณฑ์ |
|---|---|---|
| 1 | **ต้องผลิตภาษา (Output)** | ผู้ใช้ต้อง**ออกเสียงพูด**ทุกครั้งที่เรียน ไม่ใช่แค่ฟัง/เลือกคำตอบ |
| 2 | **ได้ตอบโต้ (Interaction)** | ต้องมีคู่สนทนาที่ "ตอบกลับ" — AI หรือบทบาทสมมติก็ได้ |
| 3 | **ความกดดันต่ำ** | ไม่มีคนตัดสิน ไม่มี leaderboard → ลด speaking anxiety ซึ่งเป็นอุปสรรคอันดับ 1 ของคนไทย |

**จุดแข็งที่แอปเรามีอยู่แล้ว** (และคู่แข่งส่วนใหญ่ไม่มีพร้อมกัน): ภาพจริง + เสียงอ่าน + **ประโยคใช้งานจริง** + ไฮไลท์คำ + สรุปวลีสำคัญ + SRS — ฟรี ไม่มีล็อกอิน ไม่มีโฆษณา ไม่เก็บข้อมูลออกจากเครื่อง

**ช่องว่างใหญ่ที่สุดของเรา: ยังไม่มี "โหมดสนทนา"** — ตอนนี้ผู้ใช้ยังเป็น "ผู้รับ" (ฟัง/อ่าน/เลือก) ไม่ใช่ "ผู้พูด"

**ข้อเสนอ:** ทำโหมด **บทสนทนาจำลอง (Role-play)** + **พูดตามเงา (Shadowing)** + **พูดคนเดียว 60 วินาที** ก่อน — ทั้งสามทำได้ด้วยเทคโนโลยีที่มีในแอปอยู่แล้ว (Web Speech API) ไม่ต้องมี backend และไม่ต้องจ่ายค่า AI

## 1. แอปใหญ่ทำอะไร และได้ผลเพราะอะไร

| แอป | โหมดที่ประสบความสำเร็จที่สุด | กลไกเบื้องหลัง | บทเรียนสำหรับเรา |
|---|---|---|---|
| **Duolingo** | เกม/สตรีค/ลีก + ล่าสุดคือ **Video Call กับ Lily** (AI สนทนาเสียง) ([Duolingo blog](https://blog.duolingo.com/ai-and-video-call/), [Nasdaq](https://www.nasdaq.com/press-release/duolingo-launches-ai-powered-video-call-android-2025-01-16)) | Gamification สร้างนิสัย/ความต่อเนื่อง ([StriveCloud](https://www.strivecloud.io/blog/gamification-examples-boost-user-retention-duolingo)) แต่ถูกวิจารณ์ว่าได้ "ความเคยชิน" มากกว่าความสามารถพูดจริง ([Zenodo](https://zenodo.org/records/20832584)) | เอา **กลไกนิสัย** (สตรีค/เป้าหมายรายวัน) มาใช้ แต่**อย่าเอาการแข่งขัน**ที่ทำให้คนกลัวผิด |
| **ELSA Speak** | **ให้คะแนนการออกเสียงทีละเสียง** + feedback ทันที + บทสนทนาตามภารกิจ | อิง CLT (สอนเพื่อสื่อสาร) + TBLT (เรียนผ่านภารกิจจริง) + เน้น **"พูดให้คนเข้าใจ" ไม่ใช่ "สำเนียงเป๊ะ"** + คะแนนผูกกับ CEFR (บริษัทระบุว่า scoring engine สอดคล้องกับผู้ประเมินมนุษย์ 93.88% ภายใน ±1 ระดับ CEFR) ([ELSA Efficacy](https://elsaspeak.com/en/efficacy)) | **นี่คือปรัชญาที่เราควรลอก**: วัด "สื่อสารได้" ไม่ใช่ "ถูกหลัก" — และให้ feedback ทันทีหลังพูด |
| **Speak** (หนุนโดย OpenAI) | **คุยกับ AI ไม่อั้น** ตามสถานการณ์ | ประสบการณ์ "ได้พูดจริงโดยไม่มีคนตัดสิน" ทำให้คนยอมจ่าย — มีรายงานว่ามูลค่าบริษัทถึงระดับ 1 พันล้านดอลลาร์และรายได้แตะ 100 ล้านดอลลาร์ ([Yahoo Finance](https://sg.finance.yahoo.com/news/1-billion-ai-startup-backed-144613265.html)) | ตลาดยอมจ่ายเพื่อ "ได้พูด" — ยืนยันว่าโหมดสนทนาคือหัวใจ ไม่ใช่คำศัพท์ |
| **Cake** | **วิดีโอสั้นจริง + ซับไตเติลคู่ (EN/TH)** เล่นประโยคซ้ำได้ | Comprehensible input ที่สนุกและทันสมัย (ยอดนิยมมากในเกาหลี/เอเชีย) ([Google Play](https://play.google.com/store/apps/details?id=me.mycake&hl=en-us&gl=us)) | ผู้ใช้อยากได้**ภาษาที่คนจริงพูด** ไม่ใช่ประโยคตำรา → เราเติม "ประโยคจากสถานการณ์จริง" ได้ |
| **Pimsleur / Michel Thomas** | เสียงก่อน ตัวอักษรทีหลัง; **พูดตั้งแต่บทแรก**; สร้างประโยคยาวแบบถอยหลัง (backward buildup) | ลดภาระการจำ ประโยคถูกประกอบขึ้นทีละส่วน ผู้ใช้พูดออกเสียงตลอดเวลา ([Pimsleur vs Michel Thomas](https://hearsaylearn.com/magazine/pimsleur-vs-michel-thomas)) | ใช้กับโหมดใหม่: **ประกอบประโยคจากวลีสำเร็จรูป** ให้ผู้ใช้พูดประโยคยาวขึ้นเรื่อยๆ |
| **HelloTalk / Tandem** | แลกภาษากับเจ้าของภาษาจริง | Interaction hypothesis — ต้องต่อรองความหมายกับคนจริง ([Bild comparison](https://www.bild.de/sprachen-lernen/tandem-vs-hellotalk/)) | เราแทนไม่ได้ (และไม่ควรแข่ง) — แต่ **เราเตรียมความพร้อมให้เขากล้าคุยกับคนจริง** ได้ |
| **Anki / Refold / Migaku** | **ขุดประโยค** + ทบทวนแบบเว้นระยะ (sentence mining + SRS) | ท่องจำระยะยาวด้วย SRS; เรียน**ประโยค**ไม่ใช่คำเดี่ยว | เรามี SRS แล้ว แต่ทบทวนแค่ "คำ" → ต้องขยายเป็น **ประโยค** |
| **Cambly / italki / Preply** | ครู/คู่สนทนาคนจริง | ได้ผลที่สุด แต่ราคาสูงและต้องนัดเวลา | วางตำแหน่ง: **"ฝึกฟรีทุกวัน แล้วค่อยไปใช้กับคนจริงอย่างคุ้มค่า"** |

## 2. หลักฐานว่าน้ำหนักควรอยู่ตรงไหน

| หลักการ | สาระ | นัยต่อดีไซน์ |
|---|---|---|
| **Comprehensible input** (Krashen) | เข้าใจข้อความที่ฟัง/อ่านได้เกือบทั้งหมดจึงเกิดการรับภาษา | เนื้อหาต้องง่ายกว่าlevel ผู้ใช้ 1 ขั้น + มีคำแปลไทยกำกับเสมอ (เราทำอยู่แล้ว) |
| **Output hypothesis** (Swain) | การ "ผลิตภาษา" ต่างจากการรับ — ต้องพูด/เขียนจึงจะพูดได้ | ทุกหน้าจอควรจบด้วยการที่ผู้ใช้**ต้องออกเสียง** |
| **Interaction** (Long) | การโต้ตอบจริงทำให้ปรับภาษาให้เข้าใจกัน | ต้องมีคู่สนทนา (แม้เป็นบทบาทสมมติ) |
| **Shadowing** | การพูดตามเสียงต้นแบบพร้อมกันช่วยการออกเสียงและความคล่อง (มี systematic review ปี 2025) ([Tandfonline](https://www.tandfonline.com/doi/full/10.1080/29984475.2025.2546827)) | ควรมีโหมดพูดตามแบบ "พูดพร้อมกัน" ไม่ใช่แค่พูดตามทีหลัง |
| **AI conversation bots ลด speaking anxiety** | งานวิจัยแบบ mixed-methods พบว่า AI ที่โต้ตอบ**พัฒนาการพูดและลดความวิตกกังวลได้มากกว่าการฝึกแบบเดิม** ([Nature HSSC](https://www.nature.com/articles/s41599-025-05550-z/metrics), [Nature 2026](https://www.nature.com/articles/s41599-026-09016-8), [Frontiers in Psychology](https://www.frontiersin.org/journals/psychology/articles/10.3389/fpsyg.2026.1799695/pdf)) | ผู้ใช้พูดกับ "เครื่อง" ได้โดยไม่กลัวหน้าแตก → **นี่คือคุณค่าหลักที่เราต้องขาย** |
| **บทบาทสมมติ + ภารกิจจริง (Role-play in TBLT)** | เรียนผ่านภารกิจที่ต้องใช้จริง ทำให้โอนย้ายไปชีวิตจริงได้ ([Mozaic journal](https://journal.unusia.ac.id/index.php/mozaic/article/view/1495)) | เนื้อหาควรจัดเป็น **สถานการณ์** (สั่งกาแฟ/ถามทาง/พบหมอ) ไม่ใช่บทเรียงตามตัวอักษร |
| **คำความถี่สูง** | คำ 1,000 คำแรกของภาษาอังกฤษครอบคลุมบทสนทนาส่วนใหญ่ ([Paul Nation](https://cms.wgtn.ac.nz/lals/resources/paul-nations-resources/paul-nations-publications/publications/documents/1993-1000-level-test.pdf)) | **ไม่ต้องสอน 10,000 คำ** — สอน ~800–1,500 คำ + วิธีใช้เป็นก้อนจะพาไปได้ไกลกว่ามาก |
| **SRS** | ทบทวนตามจังหวะที่ใกล้ลืม → จำระยะยาว | ต่อยอดจากคำ → **วลีและประโยค** |
| **ตลาดไทยกำลังโตจาก AI** | สื่อธุรกิจไทยรายงานว่า AI กำลังเปลี่ยนธุรกิจเรียนภาษาอังกฤษผ่านมือถืออย่างชัดเจน ([Marketeer](https://marketeeronline.co/archives/436257)) | จังหวะเวลาดี แต่ต้องมี "จุดที่ AI ยังทำได้ไม่ดี" เป็นจุดแข็งของเรา (ดู §3) |

## 3. จุดแข็งที่เรามีแล้ว vs ช่องว่างที่ทำให้ "ยังพูดไม่ได้"

### 3.1 ทุนเดิมของเรา (ต้องรักษาและขยาย)

| สิ่งที่เรามี | ทำไมมีค่าเชิงกลยุทธ์ |
|---|---|
| **ภาพถ่ายจริง + คำ + IPA + คำแปล** | ช่วยความจำแบบ dual coding (ภาพ+คำ) และผู้ใหญ่ไทยชอบเห็นภาพ |
| **ประโยคใช้งานจริงทุกคำ** | ตรงกับหลัก "เรียนประโยค ไม่ใช่คำเดี่ยว" |
| **ไฮไลท์คำแบบคาราโอเกะ** | ทำให้เชื่อม "เสียง ↔ ตัวอักษร" ได้ทันที — เป็นพื้นฐานของ shadowing |
| **สรุปวลีสำคัญ (keyVocab)** | นี่คือ **"ก้อนภาษา" (chunks)** ซึ่งเป็นสิ่งที่ทำให้พูดได้จริง — ควรยกระดับเป็นพระเอกของแอป |
| **SRS (SM-2) + สถิติ** | รากฐานสำหรับขยายไปทบทวนระดับประโยค |
| **ฝึกออกเสียง + ให้คะแนนทีละคำ** | ฐานของ output (แต่ยังไม่พอ) |
| **ไม่ต้องล็อกอิน/ไม่มีโฆษณา/ข้อมูลอยู่ในเครื่อง** | จุดขายจริง โดยเฉพาะกับคนที่กลัวพูดผิด |
| **PWA ใช้ได้ออฟไลน์** | ฝึกบนรถเมล์/ที่ไม่มี wifi ได้ = ฝึกได้ทุกวัน |

### 3.2 ช่องว่าง (เรียงตามความสำคัญต่อเป้าหมาย "พูดได้")

| # | ช่องว่าง | ผลที่เกิดขึ้น | ความยากในการแก้ |
|---|---|---|---|
| 1 | **ไม่มีโหมดสนทนา/ตอบโต้** | ผู้ใช้ไม่เคย "คุย" จริง พูดได้แค่ประโยคเดี่ยว | กลาง (บทบาทสมมติ) / สูง (AI เสรี) |
| 2 | **ไม่มี SRS ระดับประโยค** | จำคำได้ แต่ประกอบเป็นประโยคไม่ทัน | ต่ำ |
| 3 | **ไม่มีบันทึกเสียงตัวเอง** | ไม่มี self-monitoring — ผู้ใช้ไม่รู้ว่าตัวเองฟังดูเป็นอย่างไร | ต่ำ (IndexedDB/Blob ในเครื่อง) |
| 4 | **ไม่มีสถานการณ์จริงเป็นชุด** | โอนย้ายไปใช้จริงช้า | ต่ำ (งานเนื้อหา) |
| 5 | **ไม่มีงานเขียนเลย** | ผู้ใช้ขอ "เขียนทั่วไป" ยังไม่ได้รับการตอบ | ต่ำ–กลาง |
| 6 | **ฝึกออกเสียงยังไม่บอกว่า "เสียงไหนผิด"** | feedback หยาบกว่าคู่แข่ง | สูงถ้าทำเอง (ต้องมีโมเดล phoneme) — เราไม่ควรแข่งตรงนี้ |
| 7 | **คำอธิบาย (tip) บางอันเป็นไวยากรณ์** | ขัดกับเป้าหมาย "ไม่เน้นไวยากรณ์" | ต่ำ (ปรับถ้อยคำ + ตัวกรองเนื้อหา) |
| 8 | **ไม่มีเป้าหมายรายวัน/นิสัย** | ผู้ใช้เลิกกลางทางได้ง่าย | ต่ำ (มีสตรีคอยู่แล้ว แต่ยังไม่เป็น "ภารกิจวันนี้") |

## 4. โรดแมปที่แนะนำ (เรียงตามผลลัพธ์ ÷ แรงที่ลง)

### เฟส 1 — "ทำให้เขาต้องพูดทุกวัน" (ทำได้ด้วยเทคโนโลยีที่มีอยู่ ไม่ต้องมี backend/AI ภายนอก)

| ลำดับ | ฟีเจอร์ | ทำไมสำคัญ | แรง |
|---|---|---|---|
| **1** | **บทสนทนาจำลอง (Role-play Dialogue)** — สถานการณ์ละ 6–10 บรรทัด ผู้ใช้รับบทหนึ่ง แอปอ่านอีกบท แล้วสลับบท | ตอบโจทย์ "พูดในชีวิตประจำวัน" ตรงที่สุด + เป็น task-based + มี interaction | กลาง |
| **2** | **พูดตามเงา (Shadowing)** — เล่นเสียงต่อเนื่อง ผู้ใช้พูดตามพร้อมกัน วัดความคล้ายด้วย STT | หลักฐานวิจัยรองรับ + ใช้ไฮไลท์คำที่มีอยู่แล้ว | ต่ำ |
| **3** | **พูดคนเดียว 60 วินาที (Daily 1-minute)** — หัวข้อประจำวัน + จับเวลา + บันทึกเสียงเก็บไว้ฟังย้อนหลัง | สร้างนิสัย "พูดทุกวัน" และลดความกลัว (ไม่มีคนฟัง) | ต่ำ |
| **4** | **เขียนจากเสียง (Dictation) + เรียงประโยค (Sentence Builder)** | ตอบโจทย์ "เขียนทั่วไป" และฝึกโครงประโยคโดยไม่ต้องสอนไวยากรณ์ | ต่ำ |
| **5** | **SRS ระดับประโยค** — "ประโยคที่ฉันพูดไม่ได้" เข้าคิวทบทวนเหมือนคำศัพท์ | ทำให้สิ่งที่พูดไม่ได้ กลับมาซ้อมจนพูดได้ | ต่ำ |
| **6** | **ภารกิจวันนี้ (Daily quest)** — 3 อย่างจบใน 5 นาที: ทวน 5 ประโยค + สนทนา 1 สถานการณ์ + พูดคนเดียว 60 วิ | เปลี่ยนแอปจาก "คลังคำศัพท์" เป็น "นิสัยประจำวัน" | ต่ำ |

### เฟส 2 — "ใช้ AI ให้บทสนทนาไม่จำกัด"

ใช้ **DeepSeek API** (คุณมีเครดิต ¥6 อยู่ในบัญชีแล้ว) ทำ 3 อย่าง:

- **a) บทสนทนาเสรีตามบทบาท** — ผู้ใช้พูดอะไรก็ได้ AI ตอบในบทบาท + แนะนำประโยคที่ดีกว่าเป็นภาษาไทย
- **b) สร้างประโยคใหม่เฉพาะบุคคล** — จากคำ/ประโยคที่ผู้ใช้พลาด ให้ AI เขียนประโยคใหม่ที่ใช้คำนั้นในบริบทชีวิตจริง
- **c) ตรวจงานเขียนสั้น** — "บันทึก 3 ประโยคประจำวัน" แล้วให้แก้ให้เป็นธรรมชาติ (ไม่สอนไวยากรณ์ แต่เสนอประโยคที่คนจริงพูด)

> ⚠️ **ข้อบังคับทางเทคนิค**: ต้องมี backend บางๆ (Vercel Function) เป็นตัวกลาง — **ห้ามใส่ API key ไว้ฝั่ง client เด็ดขาด** และควรจำกัดโควตาต่อผู้ใช้/วัน เพราะมีค่าใช้จ่ายจริง

### เฟส 3 — "ของจริง"

- **ฟังของจริง**: คลิป/เสียงจากคลัง CC หรือ YouTube embed พร้อมซับไตเติลคู่ (แบบ Cake) — ระวังลิขสิทธิ์
- **เทียบเสียงตัวเองกับเจ้าของภาษา**: อัดไว้ข้างกัน ฟังสลับไปมา
- **ประเมินความ "เข้าใจได้" (intelligibility)** ไม่ใช่ "สำเนียงเป๊ะ" — ตามปรัชญาของ ELSA
- **ชุมชน/คู่แลกภาษา** หรือ **ตลาดครูจริง**: เราเตรียมความพร้อมให้ผู้ใช้ไปคุยกับคนจริงอย่างคุ้มค่า
- **คะแนนความพร้อมระดับ CEFR** เพื่อให้ผู้ใช้รู้ว่าตัวเองอยู่ตรงไหน

## 5. สเปกย่อของ 3 ฟีเจอร์ที่ควรทำก่อน

### A. บทสนทนาจำลอง (Role-play Dialogue) — แนะนำให้ทำเป็นอันแรก

**โครงข้อมูล** (ต่อท้ายไฟล์คำศัพท์ที่มีอยู่)
```json
{
  "id": "dlg-cafe-order",
  "title": "สั่งกาแฟ",
  "titleEn": "Ordering coffee",
  "level": "A2",
  "emoji": "☕",
  "imageQuery": "coffee shop counter",
  "lines": [
    { "who": "staff", "en": "Hi, what can I get for you?", "thai": "สวัสดีครับ รับอะไรดีครับ" },
    { "who": "me",    "en": "Could I get a medium latte, please?", "thai": "ขอลาเต้แก้วกลางครับ",
      "keyPhrases": [{ "en": "Could I get", "thai": "ขอ...ครับ" }, { "en": "a medium latte", "thai": "ลาเต้แก้วกลาง" }] }
  ]
}
```

**ขั้นตอนในแอป**
1. เลือกสถานการณ์ → เห็นภาพ + บริบทภาษาไทยสั้นๆ ("คุณอยู่ร้านกาแฟ ต้องสั่งเครื่องดื่ม")
2. แอปอ่านบทคู่สนทนา (TTS + ไฮไลท์คำ) → **ผู้ใช้พูดบทของตัวเอง** (STT ให้คะแนน)
3. ถ้าคะแนน ≥ 70% ไปบรรทัดถัดไป (ข้ามได้เสมอ — ห้ามบังคับให้ท้อ)
4. จบแล้ว **สลับบท** แล้วเล่นอีกรอบ (รอบสองจะพูดบทที่ยากกว่า = เรียนรู้สองทาง)
5. สรุป: "วลีที่คุณใช้ได้แล้ววันนี้ 5 ประโยค" → เข้าคิว SRS ระดับประโยค

**ทำไมออกแบบแบบนี้**: เป็น task-based + ต้องผลิตภาษา + มีการโต้ตอบ + ไม่มีไวยากรณ์ + จบใน 2 นาที

### B. พูดตามเงา (Shadowing)
เล่นเสียงประโยคต่อเนื่อง **โดยไม่หยุด** พร้อมไฮไลท์คำ → ผู้ใช้พูดตามพร้อมกัน → จบแล้วเทียบข้อความที่ STT จับได้
**ข้อสำคัญ**: ต้องมีโหมด "ช้า 70%" และไม่ตัดสินถูก/ผิดเป็นรายคำ (shadowing เน้นจังหวะ/ความคล่อง) — ให้คะแนนเป็น "ความต่อเนื่อง" แทน

### C. พูดคนเดียว 60 วินาที (Daily 1-minute)
หัวข้อมาจากคำที่เพิ่งเรียน ("เล่าเกี่ยวกับบ้านของคุณ โดยใช้คำว่า living room, kitchen, balcony")
→ กดอัด → จับเวลา 60 วิ → หยุด → เล่นย้อนหลัง → ให้คะแนนตัวเอง 1–5 → เก็บเสียงไว้ในเครื่อง (IndexedDB)
**คุณค่า**: เป็น "แฟ้มสะสมเสียง" ของผู้ใช้ → ฟังย้อนหลัง 1 เดือนจะเห็นพัฒนาการ = แรงจูงใจที่ทรงพลังที่สุด

## 6. ตัวชี้วัดความสำเร็จ (วัดให้ตรงเป้าหมาย)

**ไม่วัด** "จำนวนคำที่ท่องได้" — **วัด** "จำนวนประโยคที่พูดออกเสียงได้จริงต่อสัปดาห์"

| ตัวชี้วัด | เป้าหมาย | ทำไม |
|---|---|---|
| จำนวนประโยคที่พูดผ่านเกณฑ์/สัปดาห์ | ≥ 15 ประโยค | พูดได้ 50 ประโยค = เอาตัวรอดในชีวิตประจำวันได้ |
| จำนวนสถานการณ์สนทนาที่จบ | ≥ 3 สถานการณ์/สัปดาห์ | วัดการนำไปใช้ ไม่ใช่การท่องจำ |
| **อัตรากลับมาพูดซ้ำวันที่ 7 (D7)** | ≥ 35% | ตัวชี้วัดสุขภาพของแอปฝึกพูด |
| คะแนนออกเสียงเฉลี่ยของประโยคเดิม (ครั้งแรก vs ครั้งที่ 3) | ดีขึ้น ≥ 15% | พิสูจน์ว่า "ฝึกแล้วดีขึ้นจริง" |
| เวลาตั้งแต่เปิดแอปถึง "ได้พูดครั้งแรก" | < 30 วินาที | ลดการเลื่อนผ่านให้เหลือน้อยที่สุด |

## 7. สิ่งที่ **ไม่ควรทำ** (กับดักที่เจอบ่อย)

1. **อย่าเพิ่มบทเรียนไวยากรณ์** — ขัดกับเป้าหมายผู้ใช้โดยตรง ถ้าจำเป็นให้สอดแทรกเป็น "เคล็ดลับการใช้" ในประโยคเท่านั้น
2. **อย่าทำหลักสูตรยาว 500 บทเรียน** — คนส่วนใหญ่เลิกกลางทาง ให้เน้น "จบสั้น ๆ ได้ทุกวัน"
3. **อย่าใส่ leaderboard/การแข่งขัน** — ขัดกับเป้าหมายลดความกลัวพูด (ใช้สตรีคส่วนตัวและความก้าวหน้าของตัวเองแทน)
4. **อย่าเก็บเสียงผู้ใช้ขึ้นเซิร์ฟเวอร์โดยไม่จำเป็น** — "เสียงของคุณอยู่ในเครื่องคุณ" คือจุดขายที่คู่แข่งใหญ่ทำไม่ได้
5. **อย่าแข่งกับ ELSA เรื่องคะแนนระดับเสียง (phoneme)** — ต้องใช้โมเดลเฉพาะทาง เราใช้ข้อจำกัดของเบราว์เซอร์ให้เป็นประโยชน์: โฟกัส "พูดให้คนเข้าใจ" และ "พูดได้ทุกวัน"
6. **อย่าใส่ API key ของ AI ไว้ฝั่ง client** และอย่าเปิดให้ใช้ AI ไม่จำกัดโดยไม่มีเพดานค่าใช้จ่าย
7. **อย่าให้ผู้ใช้ต้องล็อกอินก่อนได้พูด** — ทุกวินาทีก่อนได้พูดครั้งแรกคือการเสียผู้ใช้

## 8. สรุปข้อเสนอ

> ถ้าจะทำเพียงอย่างเดียว: **ทำ "บทสนทนาจำลอง"**
> เพราะมันเปลี่ยนแอปเราจาก "คลังคำศัพท์ที่มีภาพสวย" → "ที่ที่ได้พูดภาษาอังกฤษจริงทุกวัน"
> และมันคือช่องว่างเดียวที่ใหญ่ที่สุดระหว่างสิ่งที่เรามี กับเป้าหมาย "พูดในชีวิตประจำวันได้"

ชุดที่แนะนำให้ทำพร้อมกัน (ทั้งหมดทำได้ในไม่กี่วัน และไม่ต้องพึ่งบริการภายนอก):
**บทสนทนาจำลอง + พูดตามเงา + พูดคนเดียว 60 วินาที + SRS ระดับประโยค + ภารกิจวันนี้ 5 นาที**
