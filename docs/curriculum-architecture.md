# โครงสร้างหลักสูตร (Curriculum Architecture) — v1

> เอกสารนี้เป็น "สัญญา" ระหว่างข้อมูล (JSON) · โค้ด (JS) · และสคริปต์ตรวจสอบ
> ถ้าจะเปลี่ยนโครงสร้าง ต้องแก้เอกสารนี้ก่อน แล้วจึงแก้ validator

---

## 1. หลักคิด 4 ข้อ (เรียงตามความสำคัญ)

1. **ผู้เรียนเริ่มจากระดับของตัวเอง** — มีแบบทดสอบวัดระดับก่อนเริ่ม และทุกบทเรียนผูกกับระดับ
2. **"พูดได้ในสถานการณ์จริง" คือเป้าหมาย** — ไม่ใช่ท่องไวยากรณ์ (ตาม AGENTS.md ข้อ 5)
3. **ทวนซ้ำได้ แต่ห้ามซ้ำโดยอุบัติเหตุ** — ทุกเนื้อหามีเจ้าของบทเรียนเดียว + มี validator บังคับ
4. **ออฟไลน์ 100%** — ทุกอย่างเป็นไฟล์ในเครื่อง ไม่มี backend ไม่มี API key

---

## 2. ลำดับชั้นของหลักสูตร

```
Level (ระดับ)  →  Unit (หน่วย)  →  Lesson (บทเรียน)  →  Task (กิจกรรมในบท)
```

| ชั้น | จำนวน | ตัวอย่าง |
|---|---|---|
| Level | 5 | `A0` เริ่มจากศูนย์ · `A1.1` · `A1.2` · `A2.1` · `A2.2` |
| Unit | 3–4 ต่อ level | "เอาตัวรอดในร้านกาแฟ" |
| Lesson | 2–3 ต่อ unit | "สั่งเครื่องดื่มได้" |
| Task | 3–6 ต่อ lesson | ฟัง · ทวนคำ · บทสนทนา · พูด · ทบทวน |

**ระดับ (Level) นิยามด้วย "สิ่งที่ทำได้" (can-do) ไม่ใช่ไวยากรณ์**

| Level | can-do ตัวอย่าง | คลังคำโดยประมาณ |
|---|---|---|
| A0 | แนะนำตัว บอกชื่อ/ตัวเลข/ราคา เข้าใจคำเดี่ยวที่ช้าและชัด | 0–120 คำ |
| A1.1 | สั่งอาหาร/เครื่องดื่มง่าย ๆ ถามราคา เข้าใจประโยคสั้น 3–5 คำ | 120–250 |
| A1.2 | ซื้อของ ถามทาง เล่าเรื่องสั้นในชีวิตประจำวัน | 250–450 |
| A2.1 | จัดการธุระ (นัดหมาย/โรงแรม) เล่าเหตุการณ์อดีต | 450–700 |
| A2.2 | พูดต่อเนื่อง 1 นาที แสดงความคิดเห็นง่าย ๆ เข้าใจบทสนทนายาว | 700–1000 |

## 3. โครงข้อมูล (JSON contract)

### 3.1 `data/curriculum.json`

```jsonc
{
  "version": 1,
  "levels": [
    {
      "id": "A1.1",
      "order": 2,
      "title": "เริ่มพูดได้จริง",
      "canDo": ["สั่งเครื่องดื่มได้", "ถามราคาได้"],
      "units": [
        {
          "id": "A1.1-U1",
          "title": "ร้านกาแฟ",
          "lessons": [
            {
              "id": "A1.1-U1-L1",
              "title": "สั่งลาเต้หนึ่งแก้ว",
              "canDo": ["สั่งเครื่องดื่มพร้อมขนาดได้"],
              "estMinutes": 5,
              "content": {
                "words": ["food-coffee", "food-milk"],      // id จาก data/words.json
                "dialogues": ["dlg-cafe"],                  // id จาก data/dialogues.json
                "listening": ["lis-cafe-01"]                // id จาก data/listening.json (เฟสถัดไป)
              },
              "tasks": [
                { "mode": "listen", "items": 5 },
                { "mode": "flashcard", "items": 4 },
                { "mode": "roleplay", "ref": "dlg-cafe" },
                { "mode": "speak", "items": 3 }
              ],
              "revisit": ["food-water"]                     // ตั้งใจทวนซ้ำ (ต้องประกาศ)
            }
          ]
        }
      ]
    }
  ]
}
```

**กติกาภาคบังคับ (validator ตรวจทุกข้อ)**

| # | กติกา | เหตุผล |
|---|---|---|
| C1 | `id` ไม่ซ้ำกันทั้งไฟล์ (level/unit/lesson) | กันอ้างอิงผิด |
| C2 | ทุกคำใน `data/words.json` ถูกอ้างใน `content.words` **ครั้งเดียว** (นับเฉพาะบทเจ้าของ) | ไม่มีคำตกหล่น/ซ้ำ |
| C3 | ทุกบทสนทนาใน `data/dialogues.json` ถูกอ้าง **ครั้งเดียว** | 同上 |
| C4 | ถ้าต้องทวนเนื้อหาเดิม ให้ใส่ใน `revisit` (ไม่นับเป็นเจ้าของ) | **ซ้ำได้เฉพาะที่ตั้งใจ** |
| C5 | `revisit` ต้องอ้างถึง id ที่มีอยู่จริง และต้องไม่ซ้ำกับ `content` ของบทเดียวกัน | กันประกาศมั่ว |
| C6 | `title` ของ lesson ต้องไม่ซ้ำภายใน level เดียวกัน | กันบทซ้ำโดยไม่รู้ตัว |
| C7 | `tasks[].mode` ต้องอยู่ในรายการที่รองรับ | กันพิมพ์ผิด |
| C8 | `estMinutes` ระหว่าง 3–8 | คุมภาระผู้เรียน |
| C9 | ทุก level มีอย่างน้อย 1 unit และทุก unit มีอย่างน้อย 1 lesson | หลักสูตรไม่ว่าง |
| C10 | `order` ของ level เรียงเพิ่มและไม่ซ้ำ | ลำดับการเรียนรู้ชัดเจน |

**โหมดที่รองรับ (`mode`)**
`listen` · `flashcard` · `quiz` · `match` · `speak` · `roleplay` · `onemin` · `review` · `placement`

### 3.2 `data/placement.json` (คลังข้อสอบวัดระดับ)

```jsonc
{
  "version": 1,
  "items": [
    {
      "id": "pl-v-001",
      "skill": "vocab",          // vocab | listening | phrase
      "level": "A1.1",           // ระดับของข้อ (ใช้เลือกข้อถัดไป)
      "prompt": "คำว่า receipt แปลว่าอะไร",
      "audioKey": "word:shop-receipt",   // ถ้าเป็นข้อฟัง
      "options": ["ใบเสร็จ", "ส่วนลด", "เงินทอน", "ถุง"],
      "answer": 0
    }
  ]
}
```

- ต้องมีข้ออย่างน้อย **4 ข้อต่อ 1 level ต่อ 1 skill** (5 level × 3 skill × 4 = 60 ข้อขึ้นไป)
- `answer` เป็น index ของข้อถูก และ `options` ต้องมี 3–4 ตัว
- ห้ามซ้ำ `id`

## 4. ระบบวัดระดับ (Placement)

**Flow**
1. หน้าแรกสุด (ครั้งแรกเท่านั้น) → "ทดสอบวัดระดับ 3 นาที" หรือ "ข้ามไปเริ่มจาก A0"
2. ทำแบบทดสอบแบบ **ปรับระดับได้ (adaptive)**: เริ่มที่ A1.1 · ถ้าตอบถูก 2 ข้อติด → เลื่อนขึ้น · ผิด 2 ข้อติด → เลื่อนลง
3. หยุดเมื่อ: ครบ 18 ข้อ หรือ confidence พอ (แต่ละ level มีคำตอบ ≥ 3 ข้อแล้ว)
4. ผลลัพธ์: `level` + คะแนนแยก 3 ทักษะ (vocab / listening / phrase) + บทเรียนเริ่มต้นที่แนะนำ

**การให้คะแนน**
- Rasch อย่างง่าย: `ability = Σ(ถูกที่ level สูง) - Σ(ผิดที่ level ต่ำ)` แล้วแมปเป็น level
- ถ้า `listening` ต่ำกว่า `vocab` เกิน 1 ขั้น → แนะนำเริ่มที่ level ของ listening (เพราะแอปเน้นฟัง/พูด)

**เก็บผล**
`store.placement = { level, skills:{vocab,listening,phrase}, takenAt, items:18 }`
- ใช้ในหน้า "เรียน" เพื่อจัดเรียงบทเรียนตามระดับ
- ทำซ้ำได้จากหน้าตั้งค่า (ผลใหม่ทับของเดิม)

## 5. การไหลของผู้เรียน (Progression)

```
placement → level → unit → lesson → tasks → (SRS) → next lesson
```

- **ปลดล็อกตามลำดับ**: lesson ถัดไปปลดล็อกเมื่อจบบทก่อน (หรือผู้ใช้กด "ข้าม" ได้ — gentle UX)
- **ทบทวน (SRS)** ทำงานแยกจากหลักสูตร: คำ/ประโยคที่พลาดจะถูกดึงมาทบทวนไม่ว่าอยู่ level ไหน
- **หน้าหลัก "วันนี้"** เสนอ: บทถัดไป + คิวทบทวน + ภารกิจ 5 นาที (มีอยู่แล้ว)

## 6. ส่วนขยายที่ออกแบบเผื่อไว้ (ยังไม่ทำใน v1)

| ส่วน | ที่ต้องเพิ่ม |
|---|---|
| Listening mode | `data/listening.json` (บทฟัง + คำถาม) — สเปกแยกใน `docs/spec-listening.md` |
| ประโยคสำเร็จรูป | `data/chunks.json` (150 ก้อน) ผูกกับ lesson ผ่าน `content.chunks` |
| ขยายคำศัพท์ | เพิ่ม `data/raw/*` แล้วรัน `build_data.py` → อัปเดต curriculum |
| ขาย/หลายผู้ใช้ | ไม่มี backend → ยังไม่รองรับ (ยกเว้นอนาคต) |
