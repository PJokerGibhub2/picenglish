# โหมดฟัง (Listening Mode) — สเปกออกแบบ v1

> เป้าหมาย: **เพิ่มทักษะการฟัง** ให้ผู้ใหญ่ไทยที่ "ฟังไม่ทัน" ไม่ใช่แค่ทายคำ
> ข้อจำกัดของเรา: ออฟไลน์ · ไม่มี backend · ไม่มี API เสียเงิน · เสียงพูดใช้ Kokoro TTS (af_heart/am_adam)

---

## 1. เจ้าดังทำกันแบบไหน (สรุปจากตลาด)

| แอป | จุดเด่นด้านการฟัง | สิ่งที่เราควรเอามา |
|---|---|---|
| **Duolingo** | ทุกบทมีเสียง, "ฟังแล้วแตะคำที่ได้ยิน", DuoRadio (บทสนทนายาว + คำถาม), Stories | ฟังแล้วแตะคำ (word spotting) + บทสนทนายาวพร้อมคำถาม |
| **ELSA Speak** | ฟังเสียงเจ้าของภาษาแล้วพูดตาม, เน้นเสียง/สำเนียง, feedback ทันที | ฟัง→พูดตาม (shadowing) + เทียบเสียง A/B |
| **LingQ** | เสียง + ข้อความซิงก์ (คาราโอเกะ), นับคำที่รู้, ฟังซ้ำได้ไม่จำกัด | ไฮไลท์คำตามเสียง (เรามีอยู่แล้ว) + นับคำที่รู้ |
| **Cake** | คลิปวิดีโอสั้น + พูดตาม + เก็บประโยค | บทสนทนาสั้นที่จบใน 30–60 วิ + shadowing |
| **BBC Learning English / ELLLO** | บทฟังแบ่งระดับ + transcript + คำถามความเข้าใจ | โครง บทฟังตามระดับ + คำถาม 3 แบบ (主旨/รายละเอียด/ตัวเลข) |

**บทเรียนจากตลาด**: ผู้เรียนฟังไม่เก่งเพราะ (1) ความเร็ว (2) เสียงเชื่อมคำ (3) คำศัพท์ไม่พอ (4) ขาดการฟังซ้ำแบบมีเป้าหมาย
→ โหมดฟังของเราต้องมี **ฟังซ้ำได้ · ปรับความเร็วได้ · มีคำถามนำ · และป้อนกลับทันที**

## 2. โครงบทฟัง (Listening Lesson)

```
บทฟัง 1 บท (30–90 วิ) = เสียง + ถอดความ + คำถาม 3–6 ข้อ + คำศัพท์เป้าหมาย 3–5 คำ
```

| องค์ประกอบ | รายละเอียด |
|---|---|
| `audioKey` | คีย์ไฟล์ Kokoro ที่สร้างไว้ (`lis:<id>` — ต้อง generate เพิ่ม) |
| `transcript` | ข้อความเต็ม (ซ่อนได้/เปิดได้ — เปิดหลังตอบครั้งแรก) |
| `questions[]` | 3–6 ข้อ ชนิดต่าง ๆ (ดูข้อ 3) |
| `targetWords[]` | คำที่ต้องได้ยินในบท (ผูกกับ SRS) |
| `level` | A0–A2.2 · ระดับกำหนดความยาว/ความเร็ว/จำนวนคำถาม |
| `speedDefault` | A0=0.75 · A1=0.85 · A2=1.0 (ปรับได้ถึง 0.6) |

**บันไดความยากตามระดับ**

| Level | ความยาว | ความเร็ว | คำถาม | ชนิดคำถาม |
|---|---|---|---|---|
| A0 | 8–15 วิ | 0.75 | 3 | ฟังคำเดี่ยว/ตัวเลข/ราคา |
| A1.1 | 15–30 วิ | 0.85 | 3–4 | gist + รายละเอียดง่าย |
| A1.2 | 30–45 วิ | 0.9 | 4 | + ตัวเลข/เวลา |
| A2.1 | 45–60 วิ | 1.0 | 5 | + ลำดับเหตุการณ์ |
| A2.2 | 60–90 วิ | 1.0 | 5–6 | + การอนุมาน (inference) |

## 3. ชนิดกิจกรรม (6 แบบ — ทำได้ทั้งหมดโดยไม่ต้องมี STT)

| # | ชนิด | วิธีเล่น | ทักษะที่ได้ | ใช้ level |
|---|---|---|---|---|
| 1 | **ฟังแล้วเลือกภาพ/คำ** | เล่นเสียง 1 คำ/วลี → เลือก 4 ตัวเลือก | จำเสียงคำ | A0–A1.2 |
| 2 | **ฟังแล้วแตะคำที่ได้ยิน** (word spotting) | เล่นประโยค → แตะคำในข้อความตามลำดับที่ได้ยิน | แยกคำในน้ำเสียงต่อเนื่อง | A1–A2 |
| 3 | **คำถามความเข้าใจ** (gist / detail / number / order / inference) | ฟังทั้งบท → ตอบ 3–6 ข้อ | ฟังจับใจความ | ทุก level |
| 4 | **เติมคำที่หาย** (dictation-gap) | ฟังแล้วพิมพ์คำที่ขาด (1–3 ช่อง) | ฟังเสียงละเอียด | A1.2+ |
| 5 | **จัดลำดับเหตุการณ์** | ฟังแล้วลาก/แตะเรียง 3–5 ประโยค | ฟังโครงเรื่อง | A2 |
| 6 | **ฟังแล้วพูดตาม** (shadowing) | ฟังทีละประโยค → อัดเสียง → A/B + ให้ดาวตัวเอง | ความคล่อง + การออกเสียง | ทุก level |

**โหมดเล่น (Session) 1 ครั้ง = 4–6 นาที**
1. `ก่อนฟัง` — 1 คำถามนำ (ภาษาไทย) เพื่อตั้งสมาธิ + คำศัพท์เป้าหมาย 3 คำ (แตะฟังได้)
2. `ฟังรอบ 1` — ฟังทั้งบท (ปุ่ม ▶ + ปรับความเร็ว 0.6/0.75/0.85/1.0)
3. `ตอบคำถาม` — ทีละข้อ มี feedback ทันที (ถูก = เขียว + เสียง chime · ผิด = แสดงเฉลย + ชี้ช่วงเวลาที่พูด)
4. `ฟังรอบ 2 + ถอดความ` — เปิด transcript พร้อมไฮไลท์คำตามเสียง (คาราโอเกะ) แล้วฟังซ้ำ
5. `เก็บคำ` — คำที่พลาด/คำเป้าหมาย → เข้า SRS + ดาว favourite ได้
6. `สรุป` — คะแนนความเข้าใจ (%) + คำที่ควรทวน + ปุ่ม "ฟังอีกครั้ง"/"บทถัดไป"

**กติกา UX (ตาม AGENTS.md ข้อ 6)**
- ไม่มีคำว่า "ตก" — ใช้ "ฟังได้ X%" และ "ลองฟังอีกรอบ"
- ฟังซ้ำไม่จำกัด ไม่มีค่าปรับ
- ทุกข้อข้ามได้ แต่บันทึกว่า "ยังไม่แน่ใจ" เพื่อมาทวน

## 4. การให้คะแนนและป้อนกลับ

| ตัวชี้วัด | คำนวณ |
|---|---|
| **comprehension** | ข้อถูก / ข้อทั้งหมด (ถ่วงน้ำหนักตามชนิด: gist 1.0 · detail 1.0 · inference 1.5) |
| **ความเร็วที่ฟังได้** | ระดับความเร็วสูงสุดที่ยังตอบถูก ≥ 70% |
| **คำที่ได้ยินไม่ชัด** | คำในข้อที่ตอบผิด → เข้า SRS ระดับคำ (ease ลด) |

**Feedback ทันทีต่อข้อ**
- ถูก → chime + "✓ เข้าใจแล้ว"
- ผิด → แสดงข้อความช่วงนั้น + ปุ่ม "ฟังท่อนนี้ช้า ๆ" (เล่นซ้ำเฉพาะช่วง 0.6x)
- ตัวเลข/เวลา → แสดงตัวเลขที่ได้ยินเทียบกับที่เลือก

## 5. โครงข้อมูล `data/listening.json`

```jsonc
{
  "version": 1,
  "lessons": [
    {
      "id": "lis-cafe-01",
      "level": "A1.1",
      "title": "สั่งกาแฟตอนเช้า",
      "contextTh": "คุณยืนอยู่หน้าร้านกาแฟ",
      "audioKey": "lis:cafe-01",          // ต้อง generate Kokoro เพิ่ม
      "seconds": 28,
      "transcript": [
        { "t": 0.0, "en": "Good morning! What can I get you?", "th": "อรุณสวัสดิ์ครับ รับอะไรดีครับ" },
        { "t": 4.2, "en": "A medium latte, please.", "th": "ลาเต้แก้วกลางครับ" }
      ],
      "targetWords": ["food-coffee", "food-milk"],
      "questions": [
        { "type": "gist", "q": "ผู้พูดอยู่ที่ไหน", "options": ["ร้านกาแฟ","โรงพยาบาล","สนามบิน","ธนาคาร"], "answer": 0 },
        { "type": "detail", "q": "ลูกค้าสั่งอะไร", "options": ["ลาเต้","ชาเขียว","น้ำส้ม","โกโก้"], "answer": 0 },
        { "type": "number", "q": "ขนาดใด", "options": ["เล็ก","กลาง","ใหญ่","ไม่ระบุ"], "answer": 1 }
      ]
    }
  ]
}
```

**กติกา validator (เหมือนหลักสูตร)**
- `id` ไม่ซ้ำ · `level` ถูกต้อง · `questions` 3–6 ข้อ · `answer` อยู่ในช่วง · ทุก `targetWords` มีใน words.json
- `audioKey` ต้องมีใน `data/audio/manifest.json` (หรือ fallback TTS)
- ทุกบทถูกอ้างใน `curriculum.json` **ครั้งเดียว**

## 6. แผนสร้างเนื้อหา (ทำได้จริงแบบออฟไลน์)

| ขั้น | งาน | เครื่องมือ |
|---|---|---|
| 1 | เขียนบทสนทนา/บทพูดเดี่ยว 40–60 บท (ระดับละ 8–12) | Codex (Luna High) |
| 2 | ตรวจความถูกต้อง + ความยาว + ระดับคำ | validator + ผู้ช่วย |
| 3 | สร้างเสียง Kokoro (บทละ 1–3 ไฟล์) | `scripts/generate_kokoro.py` (ขยายคีย์ `lis:`) |
| 4 | สร้างคำถาม 3–6 ข้อ/บท + ผูกคำเป้าหมาย | Codex + validator |
| 5 | ทดสอบการเล่นจริง + ไฮไลท์คาราโอเกะ | E2E |

> ขนาดประมาณ: 50 บท × 40 วิ ≈ 33 นาทีเสียง ≈ 3–4 MB (mp3 32 kbps) — รับได้

## 7. สิ่งที่ยังไม่ทำใน v1 (บันทึกไว้)

- วิดีโอ/คลิปจริง (ต้องมีไฟล์วิดีโอ + ลิขสิทธิ์)
- สำเนียงหลายแบบ (Kokoro มีหลายเสียง — ทำได้ใน v2: เลือกสำเนียงอเมริกัน/อังกฤษ)
- ฟังแล้วพิมพ์ทั้งประโยค (dictation เต็ม) — อยู่ในคิวถัดไป
- วัดผลเทียบผู้เรียนคนอื่น (leaderboard) — **ไม่ทำ** ตามหลัก gentle UX
